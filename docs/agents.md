# 与智能体对话

每个对话对应一个官方 CLI 的原生会话，同一时间最多运行一个任务；同一项目中可以同时运行多个对话。

## 输入框

| 操作 | 说明 |
| --- | --- |
| Enter / Shift + Enter | 发送 / 换行 |
| `/` | 打开命令列表；↑ / ↓ 选择，Tab 或 Enter 补全，Esc 关闭 |
| `@文件名`、`@src/` | 搜索并引用项目中的文件或目录；含空格的路径会自动加引号 |
| Shift + Tab | 切换 Normal / Plan 模式 |

输入框底部的菜单可以选择：

- **槽位**：使用哪个账号，见[账号与槽位](accounts.md#在对话中使用槽位)。
- **模型与思考强度**：列表用当前账号从 CLI 实时读取，只显示该模型支持的强度；选「跟随默认」则使用 CLI 的默认配置。
- **权限模式**：见下文[权限模式](#权限模式)。旧版本升级来的对话默认为「按需审批」。
- **工作模式与角色**：Normal / Plan；Codex 还可以选择默认、代码审阅、架构设计三种角色预设。

这些设置按对话保存，从下一轮开始生效，运行中不能修改。手机上槽位、权限和工作模式按钮只显示图标。

**草稿**：输入框中的文字按用户、项目和对话保存在浏览器的 `localStorage`，切换页面、刷新或关闭后都能恢复。服务端收到消息后才清除草稿，发送失败会保留。草稿不跨设备同步，清除浏览器数据会删除草稿。

**文件引用**：每条消息最多引用 8 个文件或目录；单个文本文件最多 64 KiB，合计最多 128 KiB；目录附带最多 100 项的列表。符号链接、环境变量密钥文件、CLI 内部配置和平台数据不能引用。文件过大或不可读时会提示错误并保留草稿，这时可以改为写出路径，让智能体自己去读。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/help` | 查看命令和快捷键 |
| `/clear` | 开始新对话，原对话保留 |
| `/model`、`/permissions` | 打开模型或权限菜单 |
| `/plan`、`/normal` | 切换工作模式，不改变权限模式 |
| `/role [default\|reviewer\|architect]` | 设置 Codex 角色预设；不带参数时打开菜单 |
| `/compact` | 压缩原生会话的上下文，网页上的历史不受影响；Claude 可在后面附加压缩要求 |
| `/pause`、`/resume` | 暂停 / 继续当前任务 |
| `/stop`、`/status`、`/diff` | 停止任务、查看当前设置、打开 Git 改动 |
| `/goal`、`/goal 目标内容` | 仅 Codex：查看目标；没有目标时创建 |
| `/goal edit [新目标]` | 仅 Codex：修改目标 |
| `/goal pause`、`/goal resume` | 仅 Codex：暂停 / 恢复目标的自动续轮 |

列表只包含网页已经支持的命令。项目自定义的 Slash Commands、skills 和插件尚未接入，输入未知命令会直接报错。

## 暂停、继续与停止

运行中可以点击输入框旁的「暂停」，之后点「继续」；也可以用 `/pause`、`/resume`。暂停和继续不会新增聊天消息，也不会替你发送“继续”之类的提示词，输入草稿保留。

- 暂停期间仍占用槽位，不能发送新消息、切换槽位或修改设置。
- 暂停的时间不计入耗时；刷新或切换页面不影响暂停状态；**服务重启会结束当前任务**。
- 「停止」会终止任务，之后不能再继续。

两种 CLI 的实现不同：

- **Codex**：使用原生协议。暂停时中断当前轮次（`turn/interrupt`），继续时在同一线程以空输入开始新的一轮，由 CLI 根据已有上下文接着做。暂停会取消当前未完成的审批、提问和平台管理的工具操作；已经完成的修改不会回滚，CLI 启动的后台命令可能继续运行。
- **Claude Code**：没有原生暂停接口，因此通过挂起本机进程实现（覆盖 CLI 及其子进程）。已经开始的 SSH 命令和同步会先执行完，到安全点才显示「已暂停」，等待期间点「继续」可以取消暂停。模型生成和 CLI 的网络超时不受本机挂起影响，暂停太久后可能连接失败。Codex 的上下文压缩期间也使用这种方式。

## Codex Goal

Goal 让 Codex 围绕一个目标自动连续执行多轮，使用 CLI 0.164.0 的原生接口。Goal 面板显示目标、状态、累计 Token 和耗时，目标内容最多 4000 字。

- 需要 Normal 模式；在 Plan 模式下请先切回 Normal。
- `/goal edit` 只改目标内容，状态、预算和累计用量不变。
- `/goal pause` 只是不再自动开始下一轮，当前一轮会继续做完；想立即停下请用普通的 `/pause`。当前轮结束后，暂停中的 Goal 会释放槽位。
- `/goal resume` 会重新检查权限和工作区，在同一线程继续，不新增用户消息。
- 服务重启或点击「停止」后不会自动续跑，需要用 `/goal resume` 恢复。如果任务还处于普通暂停状态，先用 `/resume` 继续当前执行，再单独恢复 Goal。
- 目标数据按用户保存，切换槽位后仍保留。读取或修改目标不会启动模型。

## Plan 模式与提问

- **Claude Code** 使用原生的 `--permission-mode plan`。计划完成后切回 Normal，再让它实施。
- **Codex** 通过 `collaborationMode` 切换工作模式，角色预设通过 `developerInstructions` 传入。

规划过程中 CLI 提出的问题会显示为选项加自由输入（Claude 支持多选），刷新页面后仍能看到待回答的问题；停止任务会取消提问。

## 权限模式

| 模式 | Claude Code | Codex |
| --- | --- | --- |
| 按需审批 | `manual`：CLI 需要权限时由你在网页上决定 | `on-request` + 工作区写入沙箱，审批交给你 |
| 自动接受编辑 | `acceptEdits`：自动接受文件编辑，其他操作按原生规则 | 不提供 |
| 自动审批 | `auto`：由 CLI 自带的审核器判断 | `on-request` + `auto_review`：由 CLI 自带的审核器判断 |
| Full access | `bypassPermissions` | `never` + `dangerFullAccess` |
| YOLO（本系统提供） | 所有进入审批流程的请求直接批准，不经过原生审核器 | 同左，对原生及兼容工具的审批都直接批准 |

CLI 自带的自动审核器仍可能拒绝操作。YOLO 不会生成审批卡片。权限模式不影响项目归属、文件同步和命令在哪里执行。

## 执行过程的显示

- 执行命令、搜索、文件操作等工具调用按组折叠显示摘要，点击展开查看输入和输出。
- 每轮结束后，进度、公开的思考摘要和工具记录收起为 `Worked for …`，最终回复保持可见；审批卡片单独显示。CLI 隐藏的原始推理不会展示。
- 每轮的执行过程和耗时保存在数据库中，刷新或切换对话后仍能查看。升级前的旧消息无法补回当时没有保存的执行过程。
- 对话右侧的短线代表各轮对话，高亮当前阅读位置；悬停预览摘要，点击跳转。手机上先点短线预览，再点卡片跳转。

## 断线与重启

- 浏览器断线重连时，事件流按 `Last-Event-ID` 补发遗漏的事件，并重新读取消息、执行过程和待审批项。
- 服务重启时，运行中的任务和执行轮次标记为“已中断”，待审批项标记为“已过期”。
- 平台只恢复自己创建的原生会话，不会导入管理员在平台外用 CLI 创建的历史。

## 命令如何在开发机执行

本机项目直接在项目目录启动 CLI，使用原生的文件和 Shell 工具。SSH 开发机上的项目按以下方式路由：

- **源码读写**：在号池机的项目镜像中进行，由同步带到开发机。
- **构建、测试、Git、安装依赖等命令**：经项目的 `remote-shell` 在开发机执行，执行前后都会同步（见[同步](projects.md#同步)）。执行器只负责准备统一路径（同路径目录、bwrap 挂载或软链接），不会改写命令内容或输出。

**Claude Code**：

- 使用隔离的 settings、固定的工具白名单和 `PreToolUse` Hook。
- Hook 检查路径是否在项目内，并把 Bash 命令改写为经 `remote-shell` 执行，然后仍由 CLI 判断权限；CLI 需要确认时，通过 stream-json 控制协议在网页上显示审批。
- Full access 使用 `bypassPermissions`，其他模式保留 `--restricted`。
- Hook 与 Hub 通过每次运行随机生成令牌的 Unix Socket 通信，超时或断开即拒绝（`onFailure: block`）。

**Codex**：

- 使用固定版本的 `app-server` JSON-RPC，启用原生 Shell、源码读取与搜索，以及 `apply_patch` 编辑；工作区模式允许修改项目镜像。
- 命令由原生命令工具经 `remote-shell` 在开发机执行，不依赖覆盖 `SHELL`。
- 原生的命令和文件修改审批接入网页；自动审批模式交给 CLI 自带的审核器。
- 新线程不再注入 `workspace_*` 工具；旧线程仍兼容，在自动审批或 Full access 下会引导其改用原生工具，避免多出平台审批。

任务正常结束前会等待同步完成，避免只改了镜像文件、还没同步到开发机就报告完成。

已有项目重新同步后会更新执行器；旧对话的系统提示可能受 CLI 快照影响，需要新建对话或压缩上下文后才生效。

参考：[OpenAI app-server](https://learn.chatgpt.com/docs/app-server)、[Claude Hooks](https://code.claude.com/docs/en/hooks)、[Claude CLI reference](https://code.claude.com/docs/en/cli-reference)、[Mutagen 安装](https://mutagen.io/documentation/introduction/installation)。Codex 的动态工具属于实验接口，升级 CLI 前请核对目标版本生成的 JSON Schema。
