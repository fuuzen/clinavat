# 与智能体对话

每个对话对应一个官方 CLI 的原生会话，同一时间最多运行一个回复；同一项目中可以同时运行多个对话。

## 输入框

| 操作 | 说明 |
| --- | --- |
| Enter / Shift + Enter | 发送 / 换行 |
| `/` | 打开命令列表；↑ / ↓ 选择，Tab 或 Enter 补全，Esc 关闭 |
| `@文件名`、`@src/` | 搜索并引用项目中的文件或目录；含空格的路径会自动加引号 |
| Shift + Tab | 切换 Normal / Plan 模式 |

输入框底部的菜单可以选择：

- **槽位**：使用哪个账号，见[账号与槽位](accounts.md#在对话中使用槽位)。
- **模型与思考强度**：列表用当前账号从 CLI 实时读取，只显示该模型支持的强度；选「跟随默认」则使用 CLI 的默认配置。
- **权限模式**：见下文[权限模式](#权限模式)，新对话默认为「按需审批」。
- **工作模式与角色**：Normal / Plan；Codex 还可以选择默认、代码审阅、架构设计三种角色预设。
- **提问**：智能体提问后等待回答的时间，以及无人回答时的处理方式，见[无人回答的提问](#无人回答的提问)。

这些设置按对话保存，从下一轮开始生效，运行中不能修改；提问设置例外，运行中也能修改，从下一个问题开始生效。手机上槽位、权限、工作模式和提问按钮只显示图标。

## 运行中发送消息

回复进行中也可以继续输入。发送按钮左侧的按钮切换发送方式，Enter 按当前方式发送：

| 方式 | 效果 |
| --- | --- |
| 引导（默认） | 消息加入当前回复，智能体在下一步看到它：Codex 立即注入当前轮次（`turn/steer`）；Claude Code 在当前工具调用结束后读到，如果回复只剩纯文本生成、没有下一步，就在这轮结束后作为新一轮处理。消息立即出现在对话中 |
| 排队 | 当前回复结束后作为新一轮发送；排队的消息显示在输入框上方，发送前可以取消，最多 20 条 |
| 打断 | 结束当前回复（已完成的修改不回滚），然后立即处理这条消息 |

如果引导消息到达时当前回复恰好结束，它会自动成为下一轮。暂停期间只能排队。排队消息保存在数据库中，账号交接时随对话保留；Hub 重启后会重新显示，等待用户继续，不会自行重放。点击「停止」或取消某条排队消息会清除对应待发输入。

## 常驻进程与空闲回收

一轮回复结束后，CLI 进程不会立即退出，而是保留到下一条消息，因此后续消息不需要重新启动 CLI 和恢复上下文。

- 进程在没有回复、没有排队消息、也没有后台任务后开始计时，空闲 5 分钟（`CLINAVAT_RUNTIME_IDLE_MS`）后退出并释放槽位。
- 进程保留期间对话显示为已完成，槽位仍由你占用。其他用户需要这个槽位、修改对话的槽位、权限或模式、压缩上下文、启动 Goal、删除对话，或同步、修改、删除项目时，空闲的进程会先自动退出；仍有后台任务时这些操作会被拒绝，需要先停止后台任务。
- 发布新版本时，部署脚本会等待所有槽位空闲，常驻进程最多会让发布推迟一个空闲周期。

Claude 自动账号模式遇到明确的订阅额度耗尽时，会等待工具和后台任务自然结束，同步并释放旧槽位，再恢复到另一个账号。切换期间可以停止对话；其他错误会保留队列并停止发送。选择规则和限制见[账号与槽位](accounts.md#claude-自动选择和切换)。

## 后台任务

Claude Code 可以把耗时命令放到后台执行（`run_in_background`），本轮回复先结束，命令继续运行。

- 运行中的后台任务显示在输入框上方，可以单独停止。
- 后台任务结束后，Claude Code 会自动开始新一轮查看结果；这一轮在对话中以「后台任务结束」的系统消息开头，审批和提问照常进行。被停止的任务不会触发新一轮。
- 后台任务在常驻进程中运行：「停止」对话、进程空闲退出前、服务重启都会结束它们。
- SSH 开发机上的后台命令同样经 `remote-shell` 执行，但不占用项目命令锁，前台命令可以同时运行。暂停对话时，平台会等待开发机上的命令到安全点，正在运行的后台远程命令会让暂停一直停在「正在暂停」，这时可以先停止该后台任务。

Codex 没有后台任务的控制接口；它启动的长命令可能在一轮结束后继续运行，进程会保留到这些命令结束后才开始空闲计时。

**草稿**：输入框中的文字按用户、项目和对话保存在浏览器的 `localStorage`，切换页面、刷新或关闭后都能恢复。服务端收到消息后才清除草稿，发送失败会保留。草稿不跨设备同步，清除浏览器数据会删除草稿。

**文件引用**：每条消息最多引用 8 个文件或目录；单个文本文件最多 64 KiB，合计最多 128 KiB；目录附带最多 100 项的列表。符号链接、环境变量密钥文件、CLI 内部配置和平台数据不能引用。文件过大或不可读时会提示错误并保留草稿，这时可以改为写出路径，让智能体自己去读。

| 命令 | 作用 |
| --- | --- |
| `/help` | 查看命令和快捷键 |
| `/clear` | 开始新对话，原对话保留 |
| `/model`、`/permissions` | 打开模型或权限菜单 |
| `/plan`、`/normal` | 切换工作模式，不改变权限模式 |
| `/role [default\|reviewer\|architect]` | 设置 Codex 角色预设；不带参数时打开菜单 |
| `/compact` | 压缩原生会话的上下文，网页上的历史不受影响；Claude 可在后面附加压缩要求 |
| `/pause`、`/resume` | 暂停 / 继续当前任务 |
| `/stop`、`/status`、`/diff` | 停止任务、查看当前设置、打开 Git 改动 |
| `/goal`、`/goal 目标内容` | 仅 Codex：查看目标；没有目标时创建 |
| `/goal edit [新目标]` | 仅 Codex：修改目标 |
| `/goal pause`、`/goal resume` | 仅 Codex：暂停 / 恢复目标的自动续轮 |

列表只包含网页已经支持的命令。项目自定义的 Slash Commands、skills 和插件尚未接入，输入未知命令会直接报错。

## 暂停、继续与停止

运行中可以点击输入框旁的「暂停」，之后点「继续」；也可以用 `/pause`、`/resume`。暂停和继续不会新增聊天消息，也不会替你发送“继续”之类的提示词，输入草稿保留。

- 暂停期间仍占用槽位，不能切换槽位或修改设置；新消息只能排队。
- 暂停的时间不计入耗时；刷新或切换页面不影响暂停状态；**服务重启会结束当前任务**。
- 「停止」会结束当前回复、常驻进程和它的后台任务，并丢弃排队消息；之后可以正常发送新消息。

两种 CLI 的实现不同：

- **Codex**：使用原生协议。暂停时中断当前轮次（`turn/interrupt`），继续时在同一线程以空输入开始新的一轮，由 CLI 根据已有上下文接着做。暂停会取消当前未完成的审批、提问和平台管理的工具操作；已经完成的修改不会回滚，CLI 启动的后台命令可能继续运行。
- **Claude Code**：没有原生暂停接口，因此通过挂起本机进程实现（覆盖 CLI 及其子进程）。已经开始的 SSH 命令和同步会先执行完，到安全点才显示「已暂停」，等待期间点「继续」可以取消暂停。模型生成和 CLI 的网络超时不受本机挂起影响，暂停太久后可能连接失败。Codex 的上下文压缩期间也使用这种方式。

## Codex Goal

Goal 让 Codex 围绕一个目标自动连续执行多轮，使用 CLI 0.164.0 的原生接口。Goal 面板显示目标、状态、累计 Token 和耗时，目标内容最多 4000 字。

- 需要 Normal 模式；在 Plan 模式下请先切回 Normal。
- `/goal edit` 只改目标内容，状态、预算和累计用量不变。
- `/goal pause` 只是不再自动开始下一轮，当前一轮会继续做完；想立即停下请用普通的 `/pause`。当前轮结束后，暂停中的 Goal 会释放槽位。
- `/goal resume` 会重新检查权限和工作区，在同一线程继续，不新增用户消息。
- 服务重启或点击「停止」后不会自动续跑，需要用 `/goal resume` 恢复。如果任务还处于普通暂停状态，先用 `/resume` 继续当前执行，再单独恢复 Goal。
- 目标数据按用户保存，切换槽位后仍保留。读取或修改目标不会启动模型。

## Plan 模式与提问

- **Claude Code** 使用原生的 `--permission-mode plan`。计划完成后切回 Normal，再让它实施。
- **Codex** 通过 `collaborationMode` 切换工作模式，角色预设通过 `developerInstructions` 传入。

规划过程中 CLI 提出的问题会显示为选项加自由输入（Claude 支持多选），刷新页面后仍能看到待回答的问题；停止任务会取消正在等待的提问。

### 无人回答的提问

提问在等待时间内没有回答时，按设置二选一：

| 方式 | 效果 |
| --- | --- |
| 视为跳过（默认） | 告诉智能体用户没有回答，让它依据已有信息继续，不要假定任何选项已获同意 |
| 转为待回答 | 问题保存到数据库，智能体被要求立即结束本轮并说明在等哪些决定；之后常驻进程按[空闲回收](#常驻进程与空闲回收)释放槽位 |

- 待回答的问题在对话中显示为「智能体在等你回答」，侧栏对话前显示问号图标。回答或「跳过并继续」会作为你的一条新消息发送，与在输入框发送相同：对话空闲时开始新一轮，仍在回复时作为引导加入。发送失败（例如槽位不可用）时问题保留，可稍后重试。
- 待回答的问题不受停止任务和服务重启影响，删除对话时一并删除。
- Codex 不能拒绝提问，转为待回答时会以「请结束本轮」作为每个问题的回答。含密码类输入的问题不会保存，到时按跳过处理。
- 等待时间 1 分钟到 24 小时，暂停期间不计时。

设置分三级，每项未设置时取上一级：

1. **对话**：输入框底部的提问菜单，发送第一条消息后可调整。
2. **用户默认**：「工作台设置 → 对话默认值」。
3. **全站默认**：管理面板「对话设置」；未设置时为视为跳过，等待时间取 `CLINAVAT_APPROVAL_TIMEOUT_MS`。

## 权限模式

| 模式 | Claude Code | Codex |
| --- | --- | --- |
| 按需审批 | `manual`：CLI 需要权限时由你在网页上决定 | `on-request` + 工作区写入沙箱，审批交给你 |
| 自动接受编辑 | `acceptEdits`：自动接受文件编辑，其他操作按原生规则 | 不提供 |
| 自动审批 | `auto`：由 CLI 自带的审核器判断 | `on-request` + `auto_review`：由 CLI 自带的审核器判断 |
| Full access | `bypassPermissions` | `never` + `dangerFullAccess` |
| YOLO（本系统提供） | 所有进入审批流程的请求直接批准，不经过原生审核器 | 同左，对原生工具的审批都直接批准 |

CLI 自带的自动审核器仍可能拒绝操作。YOLO 不会生成审批卡片。权限模式不影响项目归属、文件同步和命令在哪里执行。

## 执行过程的显示

- 执行命令、搜索、文件操作等工具调用按组折叠显示摘要，点击展开查看输入和输出。
- 每轮结束后，进度、公开的思考摘要和工具记录收起为 `Worked for …`，最终回复保持可见；审批卡片单独显示。CLI 隐藏的原始推理不会展示。
- 每轮的执行过程和耗时保存在数据库中，刷新或切换对话后仍能查看。
- 对话右侧的短线代表各轮对话，高亮当前阅读位置；悬停预览摘要，点击跳转。手机上先点短线预览，再点卡片跳转。

## 消息的显示

- **长消息折叠**：你发出的消息超过约 12 行高度时，只显示开头约 8 行，点「展开全文」查看全部，避免粘贴的日志或需求说明占满屏幕。智能体的回复不折叠。
- **流程图**：消息、思考摘要和 Markdown 文件中的以下代码块会渲染成图表：

  | 代码块 | 语法 |
  | --- | --- |
  | ` ```mermaid ` | [Mermaid](https://mermaid.js.org/)，支持流程图、时序图、类图、状态图、ER 图、甘特图、饼图、思维导图等 |
  | ` ```flow ` / ` ```flowchart ` | [flowchart.js](https://flowchart.js.org/)（Typora 等编辑器的写法）；内容以 `flowchart`、`graph` 等 Mermaid 图表类型开头时按 Mermaid 渲染 |

  图表右上角可以切换源码、放大查看和复制源码；语法有误时显示错误原因和源码。智能体还在输出时，图表等内容停顿后再更新，暂时无法解析的部分保留上一次的结果。图表按当前外观配色，切换外观后重新绘制。
- 图表在浏览器中渲染，Mermaid 使用严格安全模式（清理标签和输出的 SVG、禁用点击脚本），flowchart.js 的输出同样经过清理，符合站点的内容安全策略。渲染器首次用到时才下载，其中 Mermaid 约 5 MiB（未压缩）。

## 断线与重启

- 浏览器断线重连时，事件流按 `Last-Event-ID` 补发遗漏的事件，并重新读取消息、执行过程和待审批项。
- 服务重启时，运行中的任务和执行轮次标记为“已中断”，待审批项标记为“已过期”，正在等待的提问随任务结束；已转为待回答的问题保留。
- 平台只恢复自己创建的原生会话，不会导入管理员在平台外用 CLI 创建的历史。

## 命令如何在开发机执行

本机项目在所用槽位的虚拟机中启动 CLI，项目目录挂载到相同路径，使用原生的文件工具；命令经 SSH 回到宿主机执行（[宿主机命令入口](vm-isolation.md#宿主机命令入口)）：Claude 的 Bash 由 Hook 改写为经 `host-shell` 在宿主机的同一目录执行，Codex 则按系统提示使用该包装脚本。宿主机模式下 CLI 本身就在宿主机运行，不经过这一层。SSH 开发机上的项目按以下方式路由：

- **源码读写**：在号池机的项目镜像中进行，由同步带到开发机。
- **构建、测试、Git、安装依赖等命令**：经项目的 `remote-shell` 在开发机执行，执行前后都会同步（见[同步](projects.md#同步)）。执行器只负责准备统一路径（同路径目录、bwrap 挂载或软链接），不会改写命令内容或输出。

**Claude Code**：

- 使用隔离的 settings、固定的工具白名单和 `PreToolUse` Hook。
- Hook 检查路径是否在项目内，并把 Bash 命令改写为经 `remote-shell` 执行，然后仍由 CLI 判断权限；CLI 需要确认时，通过 stream-json 控制协议在网页上显示审批。
- Full access 使用 `bypassPermissions`，其他模式保留 `--restricted`。
- 一轮以 CLI 的 `result` 为结束，最终回答此时确定；进程继续常驻，见[常驻进程与空闲回收](#常驻进程与空闲回收)。后台任务通过 `task_*` 和 `background_tasks_changed` 事件跟踪，用控制协议的 `stop_task` 停止；任务结束后 CLI 自行开始的一轮由平台记录为新的执行轮次。
- Hook 通过 stream-json 控制协议的 `hook_callback` 回调到 Hub，与对话共用 CLI 的标准输入输出，不经过任何 socket。Hub 对回调总是返回格式合法的允许或拒绝，处理出错时一律拒绝；回调超时，CLI 会拒绝执行该工具。任何工具结果如果没有经过这道回调，Hub 会立即停止本次运行。

**Codex**：

- 使用固定版本的 `app-server` JSON-RPC，启用原生 Shell、源码读取与搜索，以及 `apply_patch` 编辑；工作区模式允许修改项目镜像。
- 命令由原生命令工具经 `remote-shell` 在开发机执行，不依赖覆盖 `SHELL`。
- 原生的命令和文件修改审批接入网页；自动审批模式交给 CLI 自带的审核器。

每轮结束后都会同步一次工作区；同步失败时会提示错误，并把项目标记为同步异常。

已有项目重新同步后会更新执行器；旧对话的系统提示可能受 CLI 快照影响，需要新建对话或压缩上下文后才生效。

参考：[OpenAI app-server](https://learn.chatgpt.com/docs/app-server)、[Claude Hooks](https://code.claude.com/docs/en/hooks)、[Claude CLI reference](https://code.claude.com/docs/en/cli-reference)、[Mutagen 安装](https://mutagen.io/documentation/introduction/installation)。Codex 的动态工具属于实验接口，升级 CLI 前请核对目标版本生成的 JSON Schema。
