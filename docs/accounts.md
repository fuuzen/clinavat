# 账号与槽位

**槽位**是一个已登录的官方 CLI 账号。每个槽位只对应一种 CLI（Claude Code 或 Codex），创建后不能更改；同一个人要同时用两种 CLI，就需要两个槽位。管理员把槽位分配给成员，成员在对话中选择用哪个槽位。

## 管理用户

管理员从侧栏头像进入「管理面板」：

- **用户与权限**：点击「创建用户」，填写用户名和至少 12 位的初始密码。新用户是普通成员；这不受 `CLINAVAT_REGISTRATION` 开关影响，也不会切换管理员自己的登录。初始密码请通过可信渠道交给成员。
- **Workspaces / 开发机连接**：可以切换到任意用户，只读查看其项目、开发机和每个项目的对话数量。创建、编辑或测试连接需要切回自己的账号。

需要开放自助注册时，设置 `CLINAVAT_REGISTRATION=true` 并重启 Hub。无论哪种方式，**新用户都没有槽位权限**，管理员自己也需要显式分配。没有槽位的用户可以管理开发机和项目，但无法启动智能体。

每位用户的卡片下方有以下操作。不能停用或删除自己，也必须至少保留一位可用的管理员。

- **修改用户名**：用户之后用新用户名登录，已登录的设备不受影响。
- **重置密码**：保存后该用户在所有设备上退出登录（重置自己的密码时保留当前这次登录）。
- **停用**：用户立即退出登录，无法再登录，系统随即回收其资源：停止正在运行的任务，解除全部槽位分配，暂停项目同步，断开开发机连接和网页终端，停止 Mutagen 守护进程，虚拟机模式下停止其工作区容器。项目、对话、开发机配置和密钥全部保留。已停用的用户不能分配槽位。任务未能及时结束时会提示稍后重试，此时用户已无法登录，可再次停用以完成回收。
- **恢复**：用户可以重新登录。停用时解除的槽位需要重新分配，项目需在工作区点「立即同步」恢复。
- **删除**：先像停用一样回收资源，再永久删除该用户的账号、项目、对话记录、开发机配置、SSH 密钥、用量记录、号池机上的项目镜像与备份、原生 CLI 会话历史（用户数据目录 `users/<user-id>/`），以及其工作区容器。开发机上的文件和本机项目的源码目录不会删除。需要输入用户名确认。

## 创建并登录槽位

1. 在「管理面板 → 槽位管理」创建槽位，例如 `slot_claude_01`，选择 Claude Code、Codex 或 Antigravity。
2. 在服务器上，以运行 Hub 的系统用户、使用该槽位的 HOME 目录完成官方登录。在槽位卡片中点击「生成登录命令」：虚拟机模式下，Hub 会先启动该槽位的虚拟机，生成的命令在虚拟机内登录，使账号从一开始就使用槽位自己的机器和出口，因此登录前需先在「网关 → 出口绑定」中为槽位选择节点。宿主机模式下生成的是宿主机命令。Docker 部署的示例：

   ```bash
   docker compose exec -e HOME=/srv/clinavat/slots/slot_claude_01 \
     -e CLAUDE_CONFIG_DIR=/srv/clinavat/slots/slot_claude_01/.claude \
     hub claude auth login
   docker compose exec -e HOME=/srv/clinavat/slots/slot_codex_01 \
     -e CODEX_HOME=/srv/clinavat/slots/slot_codex_01/.codex \
     hub codex -c 'cli_auth_credentials_store="file"' login --device-auth
   docker compose exec -e HOME=/srv/clinavat/slots/slot_agy_01 \
     -e AGY_CLI_DISABLE_AUTO_UPDATE=true hub agy
   ```

   已登录的槽位在迁移数据目录或改为虚拟机运行时不需要重新登录，登录状态随槽位目录保留。重新登录前，先停止所有正在使用该槽位的任务；生成登录命令时会拒绝仍在运行或查询额度的槽位，并预先准备 CLI 机器身份。目前支持 Claude Code 的 claude.ai OAuth 登录、Codex 的文件方式认证和 Antigravity 的个人 Google 账号登录，见下文[Antigravity 槽位](#antigravity-槽位)。
   Claude 槽位也可以改用**长期令牌**，见下文。
3. 在槽位卡片上点击用户选择框，搜索并选择一位成员即保存；选择「未分配」则取消分配。一个用户可以拥有多个槽位。早期版本中多人共享的槽位会显示“待整理”，需要管理员手动选择一位使用者。
4. 卡片右上角的开关用于启用 / 停用槽位；正在使用的槽位要等任务结束后才能调整。

点击槽位名称旁的铅笔可以改名，改名随时可做，不影响正在运行的任务。

**删除槽位**只能在槽位停用且没有任务和额度查询时进行，需要输入槽位 ID 确认。删除会移除槽位的登录凭据或长期令牌、槽位目录、额度记录和模型列表、用户分配，以及虚拟机模式下槽位的虚拟机。

虚拟机的固定地址和机器身份不会释放：网关按地址绑定出口，地址若分给新机器，新账号就会沿用旧账号的出口。删除后它们在「网关 → 出口绑定」中显示为「已删除」，不再需要时可在那里解除绑定。用相同 ID 新建的槽位会沿用这个地址、机器身份和出口绑定，但需要重新登录。选用过该槽位的对话会保留，下次发送时需改选其他槽位；用量统计按槽位 ID 保留历史记录。

### 槽位虚拟机时区

管理员在「网关 → 出口绑定」中可以同时选择槽位的代理节点和时区，也可以只修改时区。切换节点时，系统会通过选中的代理查询真实出口 IP 的地理位置，自动预选对应的 IANA 时区，并显示出口 IP 和位置；也可点击「按出口 IP 推荐」重新查询。管理员可以搜索时区后手动覆盖，查询失败不影响手动保存。选择「跟随默认」时沿用 Hub 的默认时区。

时区变更需要槽位空闲。保存时回收空闲的常驻 CLI，正在运行的任务或额度查询会阻止修改；之后的登录、对话和探针都使用新时区。已启动 VM 的系统时区会立即更新，停止或尚未创建的 VM 在下次启动时应用。时区与虚拟机身份一起持久保存，重建 VM 后仍保留；出口绑定应用失败时恢复原时区。宿主机模式没有独立的槽位时区。

### Claude 长期令牌（setup-token）

不方便进入服务器登录时，可以在任意装有 Claude Code 的电脑上运行 `claude setup-token`，在浏览器中授权后得到一个以 `sk-ant-oat` 开头、约一年有效的令牌，然后在槽位卡片的「登录方式」中粘贴并点击「改用长期令牌」。需要订阅账号；修改前先停止使用该槽位的任务。

- **存放**：令牌用 `CLINAVAT_MASTER_KEY` 加密后保存在 `accounts/slot-tokens/`，不写入槽位 HOME，也不会返回给网页。启动 CLI 时通过环境变量 `CLAUDE_CODE_OAUTH_TOKEN` 交给 CLI；虚拟机模式下经标准输入传入虚拟机，不出现在宿主机的进程参数中。
- **原登录会被删除**：改用令牌时会删除槽位中原有的浏览器登录（`claudeAiOauth` 和 `oauthAccount`），以免智能体还能读到不再使用的凭据。改回浏览器登录后需要重新生成登录命令登录。
- **只有推理权限**：令牌不能读取订阅额度和账号资料，所以额度只在对话运行时由 CLI 的额度事件更新，也查不到订阅档位。这类槽位**不参与 Claude 自动选择**，只能作为固定账号使用。
- **不会刷新**：令牌没有刷新令牌，不会和运行中的 CLI 争用刷新；到期或在 claude.ai 撤销后需要重新生成并更换。设置时填写的有效期用于显示到期日，见下文「登录状态」。令牌长期有效，泄露的影响比浏览器登录更大，请只把这类槽位授权给可信用户。

### Antigravity 槽位

Antigravity 槽位运行 Google 的 Antigravity CLI（`agy`），使用个人 Google 账号的订阅额度。

- **登录**：运行生成的登录命令后，在 agy 中选择用 Google 账号登录。服务器上不会自动打开浏览器：在自己的电脑上打开终端里显示的链接，登录后把页面给出的授权码粘贴回终端，完成首次设置后输入 `/exit` 退出。登录前先在「网关 → 出口绑定」中为槽位选择节点，并按出口所在地设置槽位时区。
- **只支持个人 Google 账号订阅**：企业账号（Gemini Enterprise、Google Cloud 项目计费）和 Gemini API key 不受支持，Hub 会拒绝这类登录。Google Workspace 账号不包含 Antigravity 套餐。
- **凭据存放**：agy 在有桌面 keyring 的电脑上把令牌存进 keyring；槽位所在的虚拟机或服务进程没有桌面会话，agy 会改为保存到槽位 HOME 的 `.gemini/antigravity-cli/antigravity-oauth-token`。访问令牌每小时由 agy 原地刷新，刷新令牌不变。
- **不支持**：自动选择和切换账号（对话可以手动换到另一个 Antigravity 槽位并继续原来的会话）、长期令牌、额度重置。

### 槽位状态

| 状态 | 含义 |
| --- | --- |
| `IDLE` | 可以使用 |
| `RATE_LIMITED` | 管理员标记为额度受限，阻止新任务 |
| `DISABLED` | 已停用，阻止新任务 |

“是否正在被使用”单独显示。这些状态只由管理员设置；自动账号选择不会修改管理员状态。修改使用权限也不会重置受限或停用状态。

## 在对话中使用槽位

- **新对话**：Claude 可选择“自动选择”或固定账号；Codex 使用固定账号。已有对话保留原来的手动选择。
- **切换账号**：已有对话可以在输入框切换到另一个**同类型**的槽位，从下一轮开始生效。切换后会清除模型和思考强度的选择，并重新读取新账号可用的模型。Claude 对话不能切换为 Codex 对话。
- **运行中不能切换**：先点击停止，等 CLI 退出、状态清理完成后再切换。切换只影响当前对话，其他对话不受影响。
- **跨账号恢复**：切换后继续使用原来的原生会话 ID。新账号需要具备对应的模型、组织策略和资源权限，否则官方 CLI 可能拒绝恢复。

### Claude 自动选择和切换

自动模式从当前用户有权限的 Claude 账号中选择，排除使用长期令牌、停用、管理员标记受限、由其他用户占用、未绑定出口或额度无法确认的账号。先检查最新的五小时、每周及相关模型窗口，默认要求每个相关窗口至少剩余 20%，可用 `CLINAVAT_AUTO_SLOT_MIN_REMAINING_PERCENT` 调整。初次选择按最小剩余比例排序；当前账号仍满足条件时优先保持它，并只检查当前账号，避免启动其他冷 VM。百分比是各账号套餐内的比例，不表示不同套餐的绝对 Token 数相同。查询可能启动已停止的槽位 VM；冷启动及租约等待不包含在 CLI 的 30 秒查询超时内。

每个相关窗口都需要 60 秒内的用量数值；单个窗口的实时事件不会更新其他窗口的时间。重新登录、令牌身份变化或收到旧账号的迟到事件时，不会沿用无法确认归属的正额度缓存。启动前还会复核当前身份对应的额度，无法确认时停止发送。

自动模式保留所选模型和思考强度，目标账号必须支持它们。只有 Claude Code 返回本轮明确的 `usage_limit_reached`、HTTP 429、拒绝的订阅窗口及未来重置时间时才自动恢复。普通限流、认证错误、组织策略、extra usage/credits 以及无法识别的错误会停止并显示原因。识别依赖 Claude Code 的结构化字段；本次按 2.1.308 接口实现，真实自然撞限验收仍见验证报告，不把模拟响应当作真实验收。

切换先等待工具、后台任务和原生排队输入自然结束，再同步项目、退出旧 CLI 并释放租约。随后用原生会话 ID 恢复，提示智能体先检查现状，避免重复有副作用的步骤。切换不依赖跨账号保留私有思考；回复可能重新生成。排队消息会随成功交接保留，切换期间可停止对话。一次恢复链最多切换三次，同一槽位不会重复尝试；所有账号都不可用时显示错误。已观察的受限窗口写入数据库，重启后仍保留，不因修改权限或启停而清除；已确认属于同一底层账号的槽位共享受限记录。过了重置时间还需重新查询额度，Hub 重启不会自动重放未完成的工作。

API 中 `slot_mode` 表示选择方式，`slot_id` 表示实际账号。创建或修改时使用 `slotMode: 'auto'` 或 `'manual'`；自动模式发送消息时省略 `slotId`。Codex 的跨账号及 Goal 尚缺授权账号实测，API 也拒绝它的自动模式。

### 同时使用的规则

- 一个槽位同一时间**只能被一位用户使用**；读取模型列表也算作使用。
- 同一用户可以同时运行多个对话，使用相同或不同的槽位都可以。例外：Antigravity 和 Codex 的会话数据中有 SQLite 数据库，各槽位虚拟机挂载的是同一份文件，而虚拟机之间没有共同的文件锁，同时打开会损坏数据库。所以同一用户的这两种 CLI，同一时间各自只能在一个槽位上运行（同一槽位中可以同时运行多个对话），在另一个槽位上启动会收到提示，请改用正在使用的槽位或等它结束。
- 槽位上的任务全部结束后，仍为上一位用户保持准备好的状态（驻留）。同一用户在任何项目中再次使用它时直接接续，不需要重新交接；其他用户、管理员修改状态、权限或登录方式、需要刷新令牌的额度查询以及 Hub 停止时，才保存该用户的状态并交还槽位。驻留的槽位对其他用户显示为空闲。
- 其他用户需要等这个槽位的所有任务和模型查询结束后才能使用，否则会收到冲突提示。
- 同一项目中并行的对话操作的是同一个目录，文件修改可能互相影响；需要隔离时请使用不同项目。修改或删除项目需要等该项目的所有对话停止。

### 撤销权限

撤销用户的权限或停用槽位时，需要等该槽位上的任务和模型查询全部结束。对话和原来的选择记录会保留，但后端会拒绝继续使用已撤销的槽位；旧页面提交过期的设置会被拒绝并刷新。

## 额度显示

槽位卡片和输入框的槽位菜单会显示各个额度窗口的已用 / 剩余百分比、重置倒计时、更新时间和查询状态。槽位图标外圈表示主额度（优先显示每周总额度），里面一圈表示 5 小时窗口（仅在服务端提供时显示）。Claude 账号有按模型单独计算的每周窗口（如 Fable）时，最里面再加一圈显示其中已用比例最高的一个，菜单中也会多一行。Antigravity 按模型分组计算额度：外圈和里圈是 Gemini 分组的每周和 5 小时窗口，最里面一圈是其他分组（Claude 与 GPT 模型）中用得最多的每周窗口；套餐不同时，有的分组只有每周窗口。菜单中的账号名旁显示订阅档位。没有任何额度数据的窗口显示为虚线，不会当作 0%；数据过期或最近一次查询失败时，继续显示上次的额度并调暗；已过重置时间的窗口显示为空并调暗，等待新的数据。

**数据来源**：只采用账号服务端返回的数据，不根据 Token 消耗推算。Claude Code 通过控制协议 `get_usage`（实验接口）读取，Codex 通过 app-server 的 `account/rateLimits/read` 读取（含积分余额和重置卡），Antigravity 通过 `agy -p /usage` 读取（只由 CLI 应答，不开启对话，也不消耗额度）。“额度受限”只来自服务端的明确信号。

活跃 Claude 会话直接接收原生 `rate_limit_event`，Codex 接收 `account/rateLimits/updated`。Claude 的 statusline 也能向本地命令提供额度百分比和窗口重置时间，但已核验的 2.1.308 / 2.1.310 仅在交互终端界面执行该命令，不适用于本项目的 `-p stream-json` 模式，因此这里使用结构化事件。`resets_at` / `resetsAt` 表示额度窗口重置时间，不表示充值到账时间。

**更新时机**：

- 对话运行中收到 CLI 的额度事件时立即推送；Codex 对话启动时会额外读取一次。
- 相关页面可见时每 90 秒向 Hub 同步一次额度，同一网页的多个位置共用一次请求；页面重新可见时也会同步。只有超过刷新周期的槽位才会真正查询。
- 后端对同一槽位每隔一个**刷新周期**才自动查询一次，最近收到对话额度事件时也会推迟补查。刷新周期由管理员在「槽位管理」中设置，默认 12 小时，对所有槽位生效。查询失败后 1 分钟重试，之后间隔依次加倍，最长不超过刷新周期，成功更新后恢复；手动刷新至少间隔 15 秒，全局最多同时 2 个查询；停用的槽位不查询。Claude Code 自身有约 60 秒缓存。

**查询方式**：优先采用现有会话的额度推送；需要补查时，复用同一槽位中已就绪、未暂停的常驻 CLI，通过它的原生控制通道读取，不创建新 HOME、不复制凭据，也不发送用户消息或启动推理。读取前后核对进程、授权版本和账号身份。常驻进程正在启动、暂停或退出，或者额度读取失败、限流时，保留历史快照并显示错误、退避，不立即另起探针。缺失窗口不当作 0%，部分事件不会更新未携带窗口的时间。

只有没有常驻会话进程时才使用独立探针。虚拟机模式下，探针与对话、模型查询、登录始终在同一槽位 VM、同一出口运行。探针在 `run/usage-probes/<slot-id>/` 下使用临时 HOME，复制槽位授权文件；Claude 还会带入槽位固定的 `machineID`、首次启动信息和必要账号身份字段，使每次查询沿用相同 CLI 标识。临时目录不包含用户的项目、插件、会话或缓存，查询结束后删除，也不把探针生成的配置写回槽位。如果查询期间 CLI 刷新了令牌，即使额度查询失败，也会在槽位授权文件没有被改动时写回。槽位正被其他短时查询使用、又没有可复用的会话进程时，只有访问令牌离过期还有 15 分钟以上才允许独立查询，以免同时刷新令牌。

**数据有效期**：最后一次额度快照保存在 Hub 数据目录中，重启后保留。临时查询失败（包括额度接口限流）会保留之前的额度并显示错误，不会判为账号缺少授权。超过**有效期**没有更新或最近一次查询失败时显示“数据已过期”。有效期与刷新周期一起在「槽位管理」中设置，默认 12 小时。运行中对话推送的额度事件随时更新数据，不受刷新周期和有效期影响；Claude 自动选择账号仍要求 60 秒内的数据，不足时会立即补查。数据按账号标识绑定，槽位改登录其他账号后旧数据会被清除。倒计时归零只表示“已到重置时间，待刷新确认”，不代表额度已经恢复。

### 订阅信息

槽位卡片（管理员）和「工作台设置 → 我的账号」（成员）会显示订阅档位和期限，只读取槽位中官方 CLI 保存的登录信息，不额外请求服务端：

| | 档位 | 开始时间 | 到期时间 |
| --- | --- | --- | --- |
| Codex | ID Token 中的 `chatgpt_plan_type`，如 Plus、Pro | `chatgpt_subscription_active_start` | `chatgpt_subscription_active_until`，剩余 7 天内以警告色显示 |
| Claude Code | `.credentials.json` 中的 `subscriptionType`，结合 `rateLimitTier` 区分 Max 5x / 20x | `oauthAccount.subscriptionCreatedAt` | Claude Code 不提供 |

- Codex 的订阅信息是 ID Token 签发时的快照，令牌刷新（约每周一次）后才更新；悬停可以看到服务端最近一次核实的时间。续费后到期时间要等下次刷新才会变化。
- 使用长期令牌的 Claude 槽位没有账号资料，不显示订阅信息。
- 这些信息来自槽位目录，使用该槽位的智能体可以修改，只用于展示。

### 登录状态

同样的位置还会显示每个槽位的登录方式和期限：

- **长期令牌**：`claude setup-token` 默认有效 1 年，但 CLI 不在任何地方记录到期时间，所以设置令牌时需要填写有效期（默认 365 天），Hub 按此计算到期日。剩余 30 天内以警告色显示，过期后需要重新生成。
- **浏览器登录**：Claude Code 和 Codex 都没有固定的到期时间，只要刷新令牌有效，CLI 会自动续期访问令牌。页面显示访问令牌的有效期（Claude `.credentials.json` 的 `expiresAt`，Codex 访问令牌的 `exp`），Codex 还显示上次续期时间（`last_refresh`），用于排查续期是否正常。刷新令牌的有效期两种 CLI 都不提供。
- `claude auth status` 和 `codex login status` 只报告是否登录、登录方式和账号，不包含到期时间，所以 Hub 直接读取登录文件，不调用这两个命令。

### 额度重置

两种 CLI 都提供额度重置，用掉后无法撤销。管理员可以重置任何槽位；成员只能重置分配给自己、且管理员在槽位卡片上勾选了「允许被分配的成员使用额度重置」的槽位。

成员可在「工作台设置 → 我的账号 → 获授权的账号槽位」查看和刷新额度，点击「使用额度重置」；也可在对话的槽位菜单中点击对应账号下方的「重置」。已获重置授权但暂不满足使用条件时，入口会保留并禁用，个人设置会显示原因，槽位菜单可通过按钮提示查看原因。管理员在管理面板的槽位卡片中操作，所有重置都需要在弹窗中确认。

长期令牌槽位和停用的槽位不能重置；同一槽位同一时间只能执行一次重置。

| | 重置内容 | 何时可用 | 实现方式 |
| --- | --- | --- | --- |
| Codex | 消耗 1 张重置卡，立即重置当前额度窗口 | 账号有可用的重置卡 | app-server 的 `account/rateLimitResetCredit/consume`；可以指定重置卡，也可以交给 Codex 选择 |
| Claude Code | 重置 5 小时额度，每周 1 次，用量仍计入每周额度 | 5 小时额度用尽、每周额度未用尽 | 在伪终端中运行交互式 Claude Code 并执行 `/limit-reset` |

- **Codex 重置卡**：额度查询时一并读取 `rateLimitResetCredits`，槽位卡片显示剩余张数和最早到期时间。没有可重置的窗口时，服务端返回 `nothingToReset`，不消耗重置卡。
- **Claude 为什么用伪终端**：`/limit-reset` 只在交互界面中可用，`-p stream-json`、Agent SDK 和控制协议都没有对应接口；`get_usage` 返回的 `juniper_tide`（每周 5 小时重置）和 `cedar_ember`（重置卡）字段也不会被填充。另外，CLI 只有在**本进程**的请求被 5 小时额度拒绝后才提供重置，新启动的进程即使账号已经用尽也会回答“isn't available right now”。
- **Claude 重置流程**：先查询一次额度，5 小时额度未用尽或每周额度已用尽时直接返回，不启动终端。之后在与额度探针相同的临时 HOME 中启动 Claude Code（haiku 模型、禁用工具），发送一条会被额度拒绝的消息；看到 “You've hit your” 提示后关闭自动弹出的额度菜单，执行 `/limit-reset`，按 CLI 输出的文字判断结果，最后再次查询额度。发出的消息如果被正常回答，说明账号未撞限，不会执行重置。
- **识别依赖 CLI 文案**：本功能按 Claude Code 2.1.310 的界面实现，CLI 的配置可以替换这些文案，无法识别时会显示 CLI 的原文并提示刷新额度确认。开启了可选重置卡（`cedar_ember`）的账号会出现选择界面，网页无法代为选择，会取消且不使用。

## 用量统计

Hub 记录每一轮对话消耗的 Token，按用户、槽位和模型汇总：

- **成员**在「工作台设置 → 用量统计」查看自己在各个槽位上的用量，只包含自己的对话。
- **管理员**在「管理面板 → 用量统计」查看所有用户在各槽位上的用量。

两处都可以选择近 7 / 30 / 90 天或全部，展开一行可查看各模型的明细。

**数据来源**：只使用官方 CLI 在对话中报告的数据，不读取第三方服务，也不额外发起请求。

- Claude Code：每个 `result` 事件中的 `model_usage_since_last_result`，即自上一个结果以来每个模型的 Token 数和 CLI 自己估算的金额。这是 CLI 的内部字段；缺少它时改为累加本轮各条 API 消息的 `usage`，按价格快照折算。
- Codex：app-server 的 `thread/tokenUsage/updated` 通知。通知给出的是线程累计值，而且会重复发送未变化的累计值，所以每个对话保存上次计入的累计值，只计入增长的部分。

**金额**：Claude 默认用 CLI 自己的估算；Codex，以及 Claude 缺少 CLI 估算的记录，按价格表折算。价格表默认是打包时的 LiteLLM 价格快照（`backend/src/token-usage/model-prices.ts`，用 `npm run prices:update -w backend` 更新），运行时不联网。订阅账号的金额只是按 API 标价折算的等价值，不是实际扣费；没有价格的模型不计金额，合计金额后会带 `+`。

**调整价格**：管理员在「管理面板 → 用量统计 → 模型价格」中：

- **导入新快照**：上传 LiteLLM 的 [`model_prices_and_context_window.json`](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json)，替换打包的快照；可以随时恢复内置快照。网页只上传其中 OpenAI 和 Anthropic 的条目，不受 Web 入口 1 MiB 请求大小的限制。
- **自定义价格**：编辑某个模型的输入、缓存读取、缓存写入和输出价格（美元 / 百万 Token），或为快照中没有的模型添加价格；有用量但缺少价格的模型会列在上方。自定义价格优先于快照，也会替代 Claude CLI 自己估算的金额，撤销后恢复原来的计算方式。

报表在查询时按当前价格表计算，所以导入和修改都会应用到已记录的用量；Claude 的 CLI 估算保存在记录中，不受快照变化影响。

**限制**：

- 从启用统计后开始记录，不回溯更早的对话。删除对话不会删除它的用量记录。
- 自动切换账号或停止对话时，进程在一轮中途被结束的那部分调用 CLI 不再报告，会少计。
- 数据来自用户自己的执行环境，只适合参考，不应作为计费依据。

## 凭据与会话数据存放

> 使用某个槽位的用户，其智能体能够读取该槽位的账号令牌。请只把槽位授权给可信用户，撤销授权后重新登录该槽位。详见[隔离边界](vm-isolation.md#共享槽位凭据)。

| 内容 | 位置 |
| --- | --- |
| 槽位授权 | 槽位 HOME 下的 `.claude`、`.codex` 或 `.gemini/antigravity-cli`，始终留在槽位内，不按对话复制 |
| Antigravity 安装身份 | 槽位 `.gemini/antigravity-cli/` 下的 `installation_id` 和 `jetski_state.pbtxt`，属于槽位，不随用户配置迁出；额度探针也带入这两个文件 |
| Claude 长期令牌 | `accounts/slot-tokens/<slot-id>.json`，用主密钥加密 |
| Claude CLI 机器身份 | `accounts/slot-cli-identities/<slot-id>.json`，并常驻槽位 `.claude/.claude.json`；与 VM 的 `/etc/machine-id` 是不同标识 |
| 用户的原生会话 | `users/<user-id>/engine-state/<engine>/`，使用槽位时以目录链接接入 |
| 用户在某槽位的运行配置 | `users/<user-id>/slot-state/<slot-id>/runtime` |
| Codex Goal 数据库 | `users/<user-id>/engine-state/codex/goals_1.sqlite` |

因为会话数据按用户保存，同一用户换槽位后仍能继续原来的对话。每一轮都会记录实际使用的槽位和凭据版本。CLI 的命令行输入历史不会跨槽位共享，Codex 的本地索引也按槽位独立保存。令牌刷新仍由官方 CLI 决定，平台无法保证提供方不会让令牌失效。

Claude CLI 的 `machineID` 属于槽位，不随用户运行配置迁出，也不因分配给其他用户而更换。升级时优先保留已有槽位标识；槽位中没有时，从具有归属记录的历史用户配置中采用现有值，仅全新槽位才创建新值。旧用户配置中的机器字段在迁出前完整备份至 `backups/slot-cli-identities/<slot-id>/`。登录或诊断产生的空备份目录与已知初始化默认字段可以安全整理；不明确的运行状态冲突仍会保留双方并阻止覆盖。

**槽位交给另一位用户前**，系统会断开上一位用户的会话目录，并清理运行缓存和索引，防止后来者看到之前的历史。系统只接入明确支持的会话目录，不复制运行中的 SQLite / WAL 文件。

## 故障处理

- **槽位交接日志**：位于 `accounts/slot-runtime/<slot-id>.json`。如果后台进程没有退出、配置不匹配或清理失败，日志会保留，槽位不会交给其他用户；未完成的恢复会阻止 Hub 启动。处于 `parked`（驻留）阶段的日志没有进程使用槽位，不阻止发布，Hub 停止时会保存并删除它。处理时先停止相关进程，备份槽位、用户状态和日志，根据错误信息修复后重启。**不要直接删除日志来绕过检查。**
- **首次接管时的残留数据**：槽位中无法确定归属的运行状态（例如登录时产生的配置）保存在 `backups/slot-runtime-v3/<slot-id>/runtime`，初始化记录在 `accounts/slot-profiles-v3/<slot-id>.json`。
- **CLI 生成的账号备份文件**：CLI 自己产生的配置备份、以及写入中断留下的临时文件，会归档到 `backups/slot-account-artifacts/<slot-id>/`。其中可能包含登录凭据，应像槽位授权一样保护。

多人共用一个订阅账号还需遵守提供方的账号与席位条款。
