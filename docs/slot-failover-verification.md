# 槽位自动切换：待验证事项

交给有权限的执行者完成。目标是判断“撞限后自动换账号继续对话”能否落地，以及设计要按什么假设来做。这份文档只安排验证，不要在验证中修改产品代码。

调查基线（2026-11-04）：分支 `feat/slot-vm-execution`，HEAD `fb7e715` 加未提交改动；Claude Code 2.1.308；codex-cli 0.164.0。执行前先记录实际版本，版本不同时要在报告中注明。

## 开始前：需要账号所有者确认

以下任一项没有确认，就停止并询问，不要自行判断：

1. **条款：** 账号的服务条款允许这样轮换使用。这是人的决定，执行者不做判断。
2. **账号范围：** 列出可用于测试的账号。只用这些账号，每个账号在 5 小时窗口内的消耗不超过 20%（或所有者指定的上限）。
3. **扣费：** 测试账号已关闭 extra usage 和 credits，或所有者接受由此产生的费用。

## 禁止事项

这些限制同样适用于执行者派生的 agent 和脚本。

- 不要让模型复述、转述或推断它的私有思考内容，也不要设计依赖这类回答的测试。
- 不要修改、替换、移植或重放思考块和签名，不要把一个账号的历史思考块发给另一账号。
- 不要用代理改写发往模型 API 的请求或响应。
- 不要用 token 差值等方式推断隐藏的思考内容。
- 不要读取、复制或打印凭据文件和令牌。
- 不要为测试而刻意耗尽额度，也不要加入任何掩盖账号关联的手段。

本次调查曾做过前几类实验，被安全分类器拦下后已经停止，**结果不作为依据，也不需要补做**。

### 立即停止的情况

- **安全分类器拦截：** 不要换措辞重试，记录发生位置后停止该测试，并报告给所有者。
- **账号出现异常信号：** 例如 `account_on_hold`、`verification_required`、`oauth_org_not_allowed`，或收到提供方的警告。停止所有账号上的测试，不要尝试恢复。

## 已确认的结果（不需要重做）

以下用官方 CLI 加本地假 API 测得，账号和凭证都是假的。其中限额错误的文案和字段与本机 8 条真实记录一致。

| 撞限或中断时的状态 | 恢复后的结果 |
|---|---|
| 响应已完整结束，下一次请求被拒 | 工具调用、工具结果和思考块都保留并发出，工具不重跑 |
| 思考和工具调用块已完成，响应没结束就断开 | 同上，工具已执行 |
| 思考已完成，正文生成到一半时断开或进程被杀 | 思考和半截正文都不会发出 |
| 思考本身还在生成 | 丢失 |
| 工具运行中进程被杀 | 工具被杀，只执行了一半，结果为 `Exit code 137` |

其他已知结论：

- **撞限后的 CLI：** 进程仍然存活；`result.subtype` 是 `success`，但 `is_error=true`、`api_error_status=429`。
- **错误分类：** `error:"rate_limit"` 也会用于“模型需要 usage credits”，不能只凭它判断额度耗尽。
- **静默丢弃：** 新账号拒绝思考块时，CLI 会删除全部思考块并重试，事件流没有提示。
- **回复文本：** 所有者已确认重新生成可以接受，不需要测试续写质量。

## 环境准备

- 2 个 Claude 槽位和 2 个 Codex 槽位，分配给同一个测试用户，并绑定好出口。Hub 用 VM 模式运行。
- 一个专用的小型测试项目，不要用 `cc-pool`。在其中放 10 个小文件，确保项目同步状态可用。
- **工作区限制：** `cc-pool` 工作区有他人未提交的改动，不要修改或提交。不要在宿主机的工作区里运行 `npm`、`git` 或 `deploy/` 脚本，原因见 [vm-isolation.md](vm-isolation.md)。
- **临时文件：** 放在 `test-results/`（已被 git 忽略），结束后删除。

### 通过 Hub 操作

| 操作 | 接口 |
|---|---|
| 发送消息并切换槽位 | `POST /api/sessions/:id/messages`，body 带 `content`、`slotId`、`model` |
| 停止当前运行 | `POST /api/sessions/:id/stop` |
| 查看每轮记录和实际槽位 | `GET /api/sessions/:id/turns` |
| 查看运行状态 | `GET /api/sessions/:id/runtime` |
| 查看额度 | `GET /api/slots/usage` |

换槽位时必须显式带 `model`，否则模型会被重置（`backend/src/routes/session-messages.ts:39`）。

### 在槽位 VM 内手动运行 CLI

手动运行只用于抓取 Hub 不记录的原始帧和调试日志，并遵守三条规则：

- **必须在 Hub 持有租约时运行：** 让同一用户在同一槽位、同一项目下保留一个空闲的常驻对话，它默认保持 5 分钟（`CLINAVAT_RUNTIME_IDLE_MS`）。否则会话会写进槽位自己的目录，之后 Hub 会以“原生会话目录含未归档数据”拒绝接入。
- **不要同时运行被恢复的会话：** 手动恢复前，确认该对话在 Hub 里没有运行。
- **命令形式：** `POST /api/admin/slots/:id/login-command` 返回的命令就是进入 VM 的正确形式，保留身份和环境变量部分，只替换最后的 argv。实例名可用 `lxc list --project clinavat` 查看。

## P0：决定方案能否成立

### T1 Claude 真实跨账号恢复

**目的：** 确认会话能否在工具循环中途换到另一个真实账号继续，以及 CLI 是否报告丢弃思考块。

**步骤：**

1. 在槽位 A 发送：`逐个读取 src/ 下的文件，每读一个就用 Bash 运行 echo <文件名> >> audit.log，全部完成后写一段总结。`
2. `audit.log` 出现至少 3 行后，调用停止接口。
3. 向同一对话发送“继续”，带上 `slotId=B` 和原来的 `model`。
4. A→B 和 B→A 各跑 5 次。
5. 每个方向额外选 1 次，按上一节的规则在目标槽位 VM 内手动恢复，用调试日志观察：

```bash
printf '%s\n' '{"type":"user","message":{"role":"user","content":"继续"}}' | \
  claude -p --input-format stream-json --output-format stream-json --verbose \
    --permission-mode bypassPermissions --setting-sources '' --tools 'Bash,Read' \
    --strict-mcp-config --mcp-config '{"mcpServers":{}}' --model <原模型> \
    --resume <native_session_id> --debug-file /tmp/t1-debug.log
grep -cE 'server rejected a thinking block|stripping all thinking' /tmp/t1-debug.log
rm -f /tmp/t1-debug.log
```

调试日志可能含敏感内容，只记录匹配数，不要保存或上传。

**记录：** 每次的成功或失败、错误原文、`audit.log` 有无重复或缺失、每轮的 `slot_id`、匹配数。

**判定：**

| 结果 | 含义 | 对设计的影响 |
|---|---|---|
| 恢复报错 | 跨账号恢复本身不可靠 | 需要压缩上下文或开新会话，自动续力要重新评估 |
| 成功，匹配数大于 0 | 思考块被丢弃 | 按“换账号后思考丢失”设计 |
| 成功，匹配数为 0 | 没有观察到丢弃 | **不能证明思考已生效**，因为这行日志的存在未经校准。设计上仍不依赖它 |

不要为了消除最后一种不确定性而越过禁止事项。如实报告“无法确认”即可。

### T2 Codex 真实跨账号恢复

**目的：** Codex 目前完全没有实测。

**步骤：** 与 T1 相同的任务和次数，换成两个 Codex 槽位，不需要手动运行 CLI。再准备一个设置了 Goal 的对话，切换后恢复 Goal。

**记录：** `thread/resume` 成功或失败、错误原文（特别留意 encrypted、invalid、reasoning 相关字样）、`Codex 恢复的会话与当前对话不一致` 是否出现、`audit.log` 是否完整、Goal 状态是否正确。

**判定：** 恢复失败时，Codex 不进入第一版的自动续力范围。

### T3 真实撞限信号

**目的：** 假 API 的限额响应是模拟的，需要用真实撞限核对识别条件。

**步骤：** 不要刻意耗尽额度。等槽位在日常使用中自然撞限（`GET /api/slots/usage` 中 `limited=true`，或窗口已满），然后在租约内用一条简短消息触发一次请求，保存原始帧。Claude 可加 `--no-session-persistence`。Codex 走 app-server，读取 `turn/completed` 和 `error` 通知。尽量覆盖 5 小时和 7 天两种窗口。

**记录（只保留这些字段，不保留内容）：**

| CLI | 字段 |
|---|---|
| Claude | `rate_limit_event` 的 `status`、`rateLimitType`、`overageStatus`；`assistant.error`；`result.is_error`、`result.api_error_status`；错误文案；几秒后进程是否存活 |
| Codex | `turn.error.codexErrorInfo`；`error` 通知的 `willRetry`；`rateLimitReachedType`；`ordinaryUsageAllowed`；进程是否存活 |

同时记录这次请求前后额度百分比有无变化。

**判定：** 给出每种 CLI 判定“额度耗尽”的字段组合，并说明如何区分 5 小时窗口、7 天窗口、模型专属窗口和 credits 不足。如果等不到自然撞限，就标为未完成，不要伪造。

## P1：决定方案怎么做

### T4 切换成本

**步骤：** 在一个上下文达到 100K token 以上的对话中，等待一次回复结束后切换槽位。目标 VM 已停止和已运行两种情况各测 3 次。

**记录：**

- 切换前最后一个请求和切换后第一个请求的 `usage`（`input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`）。
- 目标账号切换前后的 5 小时和 7 天百分比。
- 从发送消息到第一个输出事件的耗时。

这些数据只用来评估成本，不要用来推断思考内容。

**判定：** 给出切换一次大约消耗多少额度，以此确定“目标账号至少剩余多少才值得切换”；并判断目标 VM 是否需要提前启动。

### T5 中断时的任务连续性

**目的：** 之前只跑过 1 次，样本太少。

**步骤：** 使用目标模型跑 10 次。任务包含不幂等的操作，例如 `n=$(cat count); sleep 5; echo $((n+1)) > count`，共 5 步。在 `sleep` 期间调用停止接口，再发送“继续”。

**记录：** `count` 的最终值与预期的偏差、模型是否先检查现状、是否重复或遗漏步骤。

**判定：** 如果重复或遗漏频繁，切换时必须等工具结束，绝不主动杀死运行中的工具，并在恢复提示中加入“先检查现状”。

### T6 切换 VM 的影响

**记录：**

- 槽位 VM 冷启动和挂载的耗时。
- `/tmp`、VM 家目录中的文件，以及后台进程在切换后的状态。
- 对话有后台任务时切换的行为（预期 `reclaim` 不会关闭它）。
- 目标槽位未绑定出口时的报错。
- 项目较多时是否遇到 `limits.max_bus_ports` 上限。

### T7 额度数据是否足够支撑自动选择

**记录：**

- 没有页面打开时，额度数据多久不更新。
- 一次查询是否会启动已停止的 VM，耗时和资源占用如何。
- 查询期间新租约等待了多久（`whileIdle`，单次查询超时为 30 秒）。
- 重置时间过后，`limited` 多久恢复为 false。
- 开启 extra usage 或 credits 的账号如何显示（只读查询已有账号，不要为此开启）。
- 不同套餐的百分比是否可比，以及 `plan` 字段的取值。

写入 `test-results/slot-failover-report.md`，并在回复中附上摘要。

```markdown
# 槽位自动切换验证报告
- 日期、Hub 提交、Claude Code 和 Codex 版本
- 使用的槽位（只写槽位 ID，不写邮箱和令牌）、各账号消耗的额度
```

报告里要区分“实测”“模拟”和“推断”。失败和无法确认都如实写，不要为了得出结论而放宽判定条件。

## 清理

- 删除 `test-results/` 下的临时文件，调试日志和原始帧不要留存。
- 确认槽位 VM 内没有测试进程残留，否则 Hub 会拒绝交接槽位。
- 不要手动删除 `accounts/slot-runtime/` 下的交接日志，见 [accounts.md](accounts.md#故障处理)。
- 测试会话记录会留在测试用户的 `engine-state` 中，列出路径后由所有者决定是否删除。
