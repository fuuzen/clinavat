# 开发机与项目

**开发机**是存放代码、执行命令的机器。**项目**是开发机上的一个代码目录。对于 SSH 开发机，号池机会保存一份项目镜像：CLI 在镜像中读写源码，构建、测试、Git 等命令则通过 SSH 回到开发机执行。

## 本机开发机（仅管理员）

管理员默认拥有一个固定的「本机开发机」，即 Hub 所在的文件系统，不能编辑或删除。普通成员看不到它。

- 创建项目时填写本机的绝对路径：已有目录直接打开，不存在则新建。
- CLI 直接在该目录工作，文件、命令、Git 和网页终端都使用这个真实路径，审批与普通项目一致。
- 不创建镜像，不使用 Mutagen、bwrap 或软链接，也不会在项目中写入 `.bin/remote-shell`。
- 删除项目只移除平台记录、断开终端，不会删除目录。

宿主机部署可以访问服务用户有权限的任意目录；Compose 部署访问的是**容器内**的目录，需要通过卷或绑定挂载提供。

> 号池机上的代码请使用本机开发机。不要再通过 SSH 把号池机自己添加为开发机，否则同一个目录会同时成为同步的两端。

## 添加 SSH 开发机

开发机需要有 Bash、SSH / SCP，以及项目目录。Mutagen 会自动在开发机上安装它需要的 agent。

1. 在「添加开发机」中填写地址、SSH 端口和用户名。
2. 把页面显示的公钥加入开发机的 `~/.ssh/authorized_keys`，或者导入一个没有口令的私钥。每个用户都有自己的 Ed25519 密钥，私钥加密保存在服务器上。
3. 点击连接。首次连接会记录主机密钥并显示指纹，请通过可信渠道核对。之后主机密钥一旦变化就会拒绝连接，系统不会自动清除 `known_hosts`。

### 跳板机

需要经过跳板机时，打开「通过跳板机连接」并填写跳板机的地址、端口和用户名。例如目标机是 `developer@dev.internal:22`、跳板机是 `gateway@jump.example.com:2222`，效果等同于：

```bash
ssh -J gateway@jump.example.com:2222 developer@dev.internal
```

- 目前支持一台跳板机。目标机地址由跳板机解析和访问。
- 跳板机和目标机分别认证，可以导入不同的私钥；没有导入时都使用平台为你生成的密钥，需要把公钥加到两台机器上。
- 跳板机需允许到目标机 SSH 端口的 TCP 转发。目标机的私钥不会上传到跳板机。
- 目录浏览、命令执行、同步和网页终端都走同一条连接路径。

### 修改连接

开发机菜单中的「编辑连接」可以修改地址、密钥或跳板机设置；私钥留空表示保留原密钥。只改名称不影响项目。修改连接或密钥前需要停止相关任务，系统会暂停关联项目的同步并关闭网页终端，项目镜像和开发机上的文件都会保留。改完后先点「测试连接」核对指纹，再在项目中点「立即同步」恢复。

## 创建项目

选择开发机，输入或浏览一个绝对路径。项目有以下几种模式：

| 模式 | 适用情况 | 工作方式 |
| --- | --- | --- |
| 远端新建 | 开发机上还没有代码 | 在开发机上创建和号池机镜像同路径的目录 `/var/tmp/clinavat-workspace/proj_<id>`，直接在该路径执行 |
| 已有目录 + bwrap（推荐） | 打开开发机上已有的代码 | 每条命令用 Bubblewrap 单独挂载，把真实目录显示在统一的工作区路径上；不影响开发机的其他进程 |
| 已有目录 + 软链接 | bwrap 不可用时的降级 | 在统一路径创建指向真实目录的软链接 |

为什么需要“统一路径”：CLI 在号池机镜像中看到的路径，与命令在开发机上执行时的路径必须一致，否则编译错误、日志里的文件路径就对不上。执行器会导出 `$CLINAVAT_PROJECT_ROOT` 指向这个路径。

- **bwrap**：在开发机安装 Bubblewrap（Debian / Ubuntu 上是 `sudo apt install bubblewrap`），并允许 SSH 用户创建挂载命名空间。系统会实际运行一次来检测，仅存在命令不算可用。
- **软链接**：Shell 中的 `PWD` 会尽量保持统一路径，但 `pwd -P`、`realpath` 等会解析出真实路径，无法做到完全一致。已存在的目录或不匹配的链接不会被覆盖。
- **自动模式**：优先 bwrap，不可用时退回软链接。之后装好 bwrap，点「立即同步」即可重新检测并升级。
- 统一路径的根目录如果属于其他用户且不可写，需要开发机管理员配置权限。

## 同步

创建项目后，Mutagen 在开发机目录和号池机镜像之间双向同步。同步使用 `two-way-resolved` 模式，开发机一侧为 alpha，两边改动冲突时以开发机的版本为准。

**默认排除**：依赖目录、常见构建产物、压缩包、日志、数据库文件、运行时 `.bin`、Git 内部目录和实际的 `.env` 文件。依赖锁文件和 `.env.example` 这类模板会保留。排除只按规则匹配路径，不按文件类型或大小判断，JSON、图片等源码需要的资源会正常同步。

**命令前后的同步**：在开发机执行命令前，会先把镜像中的修改推到开发机；命令结束后再把开发机上的变化拉回镜像。同步出错时命令不会执行，并显示错误。这只是“同步屏障”，不是事务：后台运行的命令、用户在外部终端同时修改同一文件等情况仍需人工协调。命令必须在前台完成。

**网页终端**：直接连接开发机，打开和退出时各同步一次，使用期间由 Mutagen 持续同步。

### 同步排除规则

Git 项目在创建和每次「立即同步」时，会读取开发机上被 Git 忽略的未跟踪文件（支持嵌套 `.gitignore`、全局排除和已跟踪文件例外），一并排除。这是当时的快照，之后新出现的忽略路径要到下次「立即同步」才更新。

非 Git 项目，或想持续排除某些输出时，在开发机的项目根目录创建 `.clinavatignore`，每行一条 [Mutagen 忽略规则](https://mutagen.io/documentation/synchronization/ignores)。空行和 `#` 开头的行会被忽略，`!` 表示重新包含。例如只排除根目录下的运行记录：

```text
/runs
/logs
```

兼容旧文件名：依次读取 `.cc-poolignore`、`.cc-pool-ignore`、`.clinavatignore`，后读取的规则优先级更高。系统第一次需要追加规则而 `.clinavatignore` 不存在时，会把优先级最高的旧文件改名为 `.clinavatignore`（不覆盖已有文件），其余旧文件继续读取。

### 首次扫描大文件

连接开发机上已有的目录时，系统会在首次同步前扫描一次，列出体积最大的目录和文件（至少 1 MB，最多 15 项），供你勾选排除：

- 依赖目录、Git 忽略路径和已有排除规则不参与统计。
- 包含 Git 跟踪文件的目录不会整体列出，而是继续展开其中未跟踪的子目录和大文件；Git 跟踪的大文件会单独标注，默认不勾选。
- 勾选的路径会作为根目录规则追加到开发机的 `.clinavatignore`，文件不存在时自动创建。
- 扫描需要开发机有 GNU find、gzip 和 base64。扫描失败不影响创建项目，只是不添加规则。

之后的「立即同步」不再扫描；要新增排除，直接编辑 `.clinavatignore`。

### 立即同步与规则变化

「立即同步」会检查排除规则是否变化。规则变了时，系统先完成旧同步，再结束旧同步会话，从开发机重建镜像。

- 旧镜像备份到数据目录的 `backups/workspaces/` 下，确认无误后可以手动删除（它们仍占用磁盘空间）。项目工作区底部会显示镜像和备份的磁盘占用。
- 旧同步无法完成时会保留原会话并报告诊断信息，避免丢失未同步的修改。
- 同步失败时会给出两端连接、扫描、文件体积和具体问题；有权限错误或文件冲突时不会显示为同步正常。
- 如果开发机就是号池机自身，系统会检测共享的数据目录，强制排除平台数据，不允许把平台数据或已有镜像当作项目源码。

## Git 与删除

- Git 命令直接在开发机执行，所以不需要同步体积很大的 `.git` 目录。Diff 包含已跟踪文件相对 `HEAD` 的暂存区和工作区改动；未跟踪的文件显示在状态中。
- 删除项目会先停止同步，再删除镜像和平台记录，**开发机上的源码会保留**。
- 删除对话只删除平台记录，官方 CLI 自己的原生日志仍保留在用户目录中。

## 网络出口

开发机的出站地址需要由上游网关加入直连名单。Clinavat 不会自动修改网关策略，也不安装代理；官方 CLI 访问官方服务使用宿主机已配置的出站网络。容器的桥接 / NAT 流量同样需要在网关上核验。代码无法保证实际的网络出口和账号风控结果。网关管理见[网关控制面](../deploy/gateway/README.md)。
