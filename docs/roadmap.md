# 技术路线

本文记录方向已经确定、但尚未完成的阶段。某个阶段完成后，相关内容会移到对应的使用文档中。

## 跨平台客户端（当前阶段）

把网页版工作台包装为 macOS、Windows、Android 和 iOS 客户端。Hub 地址在打包时通过环境变量指定，运行时可以修改和切换。代码已经完成，还需要在各平台实际验证，见[客户端](client.md)。

桌面客户端也是下一阶段的基础，届时它将承载本机开发机的守护进程。移动端只用于查看和操作工作台，不承担开发机。

## 本机开发机（下一阶段）

### 目标

用户在自己的 Windows 或 macOS 电脑上登录桌面客户端后，开发机列表中会多出一台「此电脑」。项目代码留在这台电脑上，构建、测试和 Git 命令也在这里执行；官方 CLI 仍然运行在 Hub 上。

### 原则

- **CLI 和账号凭据不离开 Hub。** 不把 CLI 放到个人电脑上运行，否则共享槽位的令牌会落到个人设备上，模型请求也会绕开网关出口。
- **所有连接由客户端发起。** 个人电脑通常位于 NAT 之后，地址也会变化。Hub 不主动连接这台电脑，也不要求它开放 sshd。
- **网页没有执行权限。** 执行命令的接口只在客户端的守护进程中，Hub 页面作为远程内容调用不到，延续客户端现有的权限隔离。

### 架构

```text
个人电脑（桌面客户端）
 ├─ 守护进程 ──WSS 443 控制通道──▶ Hub：命令、终端、Git、目录浏览、同步屏障、在线状态
 └─ Mutagen ──SSH over WSS────────▶ 同步入口 ──▶ 用户 VM 内的 mutagen-agent（项目镜像）
```

- **控制通道**：客户端登录后与 Hub 保持一条 WebSocket 长连接，Hub 经由它下发命令、终端、Git 和目录浏览请求，并通过心跳判断这台电脑是否在线。
- **反转同步方向**：Mutagen 运行在个人电脑上，由它经 WSS 隧道发起 SSH 连接，连到 Hub 侧的同步入口。入口只允许启动 mutagen-agent，并用 bwrap 把它限制在该项目的镜像目录内。首次同步可能有数 GB，这部分流量由独立进程转发，不经过 Hub 主进程。
- **remote-shell**：改为通过控制通道请求客户端执行命令；命令前后的同步屏障改为请求客户端执行 `mutagen sync flush`。LXD 模式下虚拟机访问不到宿主机，由 Hub 在用户 VM 内常驻一个中继，为 `remote-shell` 提供 Unix socket。
- **开发机类型**：新增 `kind='client'`，界面上叫「此电脑」，不复用管理员的 `local`。接入前，先把前后端约 80 处 `execution_mode` 和 `kind` 判断收拢为统一的执行传输接口，包括 exec、flush、status 和 terminal。

### 路径

CLI 在 Hub 镜像中看到的路径，原本要与命令在开发机上执行时的路径一致，见[开发机与项目](projects.md#创建项目)。

| 平台 | 方案 |
| --- | --- |
| macOS | 沿用统一路径，用软链接把真实目录映射到镜像路径。需要处理 `/var` 实际是 `/private/var` 的问题，以及默认文件系统不区分大小写 |
| Windows | 无法统一路径，降级为双路径：在 system prompt 中追加两个根路径的对应关系，让模型执行命令时使用客户端路径 |
| Windows + WSL2 | 在 WSL 中运行守护进程，按 Linux 处理 |

只靠 system prompt 并不可靠，Windows 还需要三层兜底：

1. **Hook 改写（Claude）**：把 `C:\…`、`C:/…`、`/c/…` 形式的路径映射回镜像路径，再通过 `updatedInput` 改写。否则 Hub 的路径校验会把 Windows 路径当作相对路径，在镜像中生成名为 `C:\…` 的文件。
2. **remote-shell 替换**：把命令中出现的镜像根路径替换为客户端路径，对 Claude 和 Codex 都有效。
3. **同步规则**：Windows 项目忽略含 `:`、`\` 等非法字符的文件名，避免同步失败导致所有命令被阻塞。

Windows 端要求安装 Git Bash，这样模型习惯的 Bash 命令和现有的同步脚本都能复用。PowerShell 留到以后评估。

### 首发范围

- 只支持 Claude Code。Codex 没有 PreToolUse Hook，命令要靠模型自己加上 `remote-shell`，读文件又用本地工具，路径出错的风险明显更高，需要单独验证后再开放。
- 先做 macOS，再做 Windows。

### 安全

- 命令以用户在个人电脑上的权限运行，没有沙箱，可以接触到浏览器数据、`~/.ssh` 和云凭据。`.env` 不参与同步，但命令仍然可以直接读取它。因此：
  - 绑定开发机前，要向用户明确说明风险并取得授权，并建议使用专用的系统账号；
  - 「此电脑」上的项目默认不允许 YOLO；
  - 客户端提供本地确认和一键断开。
- 一旦 Hub 被攻破，所有在线的个人电脑都会受影响。控制通道必须按用户和设备鉴权，且能随时吊销某台设备。
- 桌面安装包需要签名和公证。常驻并接受远程命令的进程容易被杀毒软件误报，需要提前与使用方沟通白名单。

### 离线

- 笔记本合盖或断网后，心跳超时就将电脑标记为离线，运行中的对话随即暂停并提示，而不是等同步屏障超时（最长 120 秒）。
- 删除项目时如果电脑离线，先吊销访问，等电脑重新连接后再终止同步并清理。
- Windows 上文件被占用很常见，同步问题需要分级处理，不能一律阻塞命令。

### 命令行工具

命令行工具与守护进程共用实现，先提供登录、关联目录、查看状态和同步功能；在终端中对话的界面放到后面。

### 实施步骤

| 步骤 | 内容 | 通过标准 |
| --- | --- | --- |
| 1. 路径验证 | 在 Windows 上用 Hook 映射加 system prompt 运行真实任务，统计路径出错率 | 出错率可以接受；否则改为 WSL2 优先 |
| 2. 同步验证 | 从 Windows 和 macOS 发起 Mutagen，经同步入口连到用户 VM 内的 agent | agent 可以预装，入口只能启动 agent，吞吐量足以完成首次同步 |
| 3. MVP | 控制通道、执行传输接口和守护进程，先支持 macOS + Claude Code | 对话、审批、终端、Git 和断线恢复都能正常使用 |
| 4. 扩展 | Windows、Codex、命令行工具 | — |

### 待决定

- Windows 用户是否必须使用原生工具链（例如 MSVC）。如果不需要，优先支持 WSL2 的成本要低一个数量级。
- 首发是否只支持 Claude Code。
